# Hop 四平台局域网键鼠与剪贴板共享：产品与开发计划

状态：产品目标已按 2026-11-09 用户确认更新；架构为待验证设计，实施和验收均未完成。本文是后续工作的路线图，不代表任何新平台功能已实现或发布。旧版 [PLAN.md](../../PLAN.md)、[协议 v1](../PROTOCOL.md) 和真实测试记录继续保留；涉及产品范围时以本计划和后续用户决定为准，不改写历史结果。

**实施优先级更新（2026-11-09）：** 用户决定先实现 macOS、Windows、Linux 作为主机，HarmonyOS 先作为接收端；鸿蒙主机暂缓，不作为本轮三平台主机的前置条件。其他三平台作为接收端的目标、剪贴板、多设备及四平台发行目标继续保留。相应的鸿蒙主机调研记作后续工作，不表示已放弃或已经可行。

## 1. 产品目标与明确范围

- 在可信局域网内连接 macOS、HarmonyOS PC/二合一、Windows、Linux；任意平台原则上均可手动选择作为接有物理键鼠的主机，其他设备作为接收端。同一共享组同时只有一个活动主机；手动交接、双方状态明确，不能静默抢占。鸿蒙及 Linux 各环境的主机能力以系统支持、合法权限与真机验证为前提，不虚报已实现。
- 支持三台及以上电脑，把电脑及其屏幕按照实际位置排列在可视化二维画布上，边缘移动跨越设备，能从远端设备继续穿越到相邻远端设备并返回主机。至少考虑上下左右、偏移、不同尺寸和缩放；跨越条件和冲突规则见第 4 节。
- 使用连接主机的键鼠控制各接收端。根据源与目标操作系统自动适配常用快捷键，让 Command+C 到 Windows/鸿蒙成为目标环境习惯的复制；Windows 的 Ctrl+C 到 Mac 成为 Command+C。普通文本由目标键盘布局和输入法处理，不把键码当 Unicode 字符。
- 主机可为每台目标设备分别设置鼠标指针灵敏度（DPI 体验，使用软件移动倍率；不声称改变鼠标硬件 DPI）、垂直/水平滚轮方向与速度、键盘映射及其他受平台支持的选项。支持常见左/右/中键、前进/后退侧键、水平与垂直滚轮；高分辨率滚动及更多按键按能力协商，不能承诺驱动私有按钮和所有手势。
- 加入文本及图片剪贴板同步；不做文件传输、跨机文件拖放、账号、云中转、互联网穿透、远程屏幕画面或应用商店分发。文件路径、文件列表和含文件引用的剪贴板格式不等于普通文本，默认不传输；非明确支持的格式忽略并提示。
- 常驻体验轻量，菜单栏/托盘提供状态和快捷操作；需要空间布局、设置及诊断时打开完整设置窗口。原生或轻量实现经原型比较后选择，不能为了 UI 隐性引入沉重常驻 Web 运行时。
- GitHub 有清晰的项目介绍、使用教程及四平台发行物。macOS、Windows、Linux 目标是普通用户可下载安装的包；HarmonyOS 提供明确标注的未签名 HAP 和用户自行签名侧载说明。正式系统签名、公证或平台信任所需账号/证书必须真实具备，不能把未签名文件称为无警告安装包。

## 2. 当前基线与迁移约束

- 截至仓库当前记录：已有 Mac Swift/AppKit 主机和 HarmonyOS ArkTS/NAPI C++ 接收端；Mac 通用构建、鸿蒙构建与安装、离线模拟及跨语言 localhost 测试有记录。双机真实键鼠输入、完整故障恢复、最低版本兼容仍未通过验收，参见 [README](../../README.md)、[恢复路径](../RESUME.md)、[验收表](../ACCEPTANCE.md)。
- v1 协议固定角色、只允许一个接收端、Mac 专属键码、明文 bearer token；当前单左右边缘与 API 不足以表达本目标。不得将其描述为已支持多机或安全加密。
- 在新版本成熟之前保留现有代码、测试、文档和产物证据；新协议单独版本化。默认不与 v1 混接、降级或共享未加密凭据；是否提供过渡兼容待安全评估及用户体验验证后决定。迁移要支持失败回滚，旧绑定不悄然转为新信任关系。
- 原计划禁止剪贴板和鸿蒙主机的产品范围已由本次用户要求更新；原有安全底线（本地输入优先恢复、合法系统授权、不伪造验收）继续有效。鸿蒙主机只有在合法能力得到证实后才能实现。

## 3. 关键可行性关口（先验证再承诺）

| 平台 | 作为主机：采集与阻止本地输入 | 作为接收端：注入 | 需做的首项验证 |
|---|---|---|---|
| macOS | 现有 CGEventTap；系统权限、Secure Input、回调停用和异常恢复仍须真测 | Core Graphics 注入候选；权限、事件标识和循环过滤待验证 | 用真实 Mac↔鸿蒙完成最小输入和恢复；证明同进程双角色安全 |
| HarmonyOS PC | 官方监听/拦截存在受限权限及适用场景，部分接口受焦点/窗口条件限制；后台全局采集和吞掉输入的合法路径**未证实** | 现有 API20+ 用户授权注入路径，实际设备输入未验 | 逐项核查 SDK、权限申领资格、后台/焦点、全键鼠/滚轮、局部吞输入及急停；出具真机证据。不使用权限旁路、系统特权或伪造场景 |
| Windows | 低级键鼠 hook 等候选，需专用消息循环、避免回调阻塞并验证停止恢复 | SendInput 候选，受 UIPI 和会话/安全桌面限制 | 实测源捕获/抑制、目标注入、睡眠恢复、完整性级别差异；不能声称支持安全桌面 |
| Linux X11 / Wayland | X11 与 Wayland 分开研究；Wayland 候选 Input Capture portal + libei，能力由 compositor 决定 | Wayland RemoteDesktop portal + libei；X11 单独验证 | 选定首批发行版和桌面会话，测授权、边缘 barrier、断开释放及托盘；不假设所有桌面均支持 portal |

官方资料：[HarmonyOS 受限权限](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/restricted-permissions/)、[HarmonyOS 输入 API](https://developer.huawei.com/consumer/en/doc/harmonyos-references/capi-oh-input-manager-h/)、[XDG Input Capture](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.InputCapture.html)、[XDG RemoteDesktop](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html)、[Windows SendInput](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput)、[Windows 低级键盘 hook](https://learn.microsoft.com/windows/win32/winmsg/lowlevelkeyboardproc)。文档只表明候选 API 和约束，不构成设备及权限可用性的证明。

若鸿蒙主机能力无法合法实现：保留鸿蒙作为接收端，记录具体不可用原因和受影响范围；继续其他不依赖它的工作，并请用户决定是否接受该限制。绝不将鸿蒙接收端成功宣传为鸿蒙主机成功。

## 4. 空间布局与切换设计

- 布局画布默认显示电脑卡片，展开后排列该电脑的各个显示器；显示电脑名、系统、连接/授权状态、显示器轮廓及当前主机标记。支持拖动对齐、缩放、键盘辅助移动、吸附/撤销/重置与实时预览；单机多显示器设备信息、排列与动态变化需平台能力验证。设备标识与屏幕标识分离，临时离线不丢布局。
- 布局采用设备屏幕二维矩形和稳定标识；画布坐标不是物理尺寸的精确测量。边缘连接需要相邻边有非零重叠区间；按边缘位置归一化映射。支持不同分辨率、DPI/逻辑像素、旋转、部分边缘重叠，横跨多台时使用确定性的命中规则；重叠布局、无邻居、多个候选和死角必须在保存前提示或阻止，避免随机穿越。间隙的吸附/连通语义在原型中测试后确定。
- 初始仅当前活动主机控制输入捕获。经安全授权后，目标不必捕获全局输入：主机维护虚拟指针和布局，持续转发到当前目标；远端到远端穿越时，先停止旧目标输入并释放实际按键，再在新目标确认后切换。网络分区、布局修订、旧 ACK 及目标离线不能造成双目标同时控制。
- 用户可在主机侧设置防误触的阈值/延迟、仅可用边缘、返回快捷键和临时暂停；默认值须通过真机可用性试验确定。按键或鼠标按钮处于按下状态时跨设备、按住拖动、接收端断线时的事件归属和释放规则必须先定义并测试。跨设备文件拖放始终不支持，应用内普通拖动需要实测。
- 手动交接主机：申请方和当前主机显示清楚、确认后释放旧捕获及所有目标按键，再完成互斥租约和新主机授权；旧主机离线时防脑裂规则需协议设计，不应因超时自动产生双主机。

## 5. 键盘、鼠标与剪贴板

### 键盘

- 平台原始码先映射到独立于系统的物理键身份（候选 USB HID usage，需逐平台验证）与左右修饰键状态；接收端映射为本地注入码。区分物理键映射和快捷键语义映射，不用 Mac keycode 作为跨平台协议。
- 默认对可识别的常用快捷键做源到目标的映射，如复制、粘贴、全选、撤销；映射表先建立四系统矩阵和精确修饰键规则，不仅简单地把每个 Ctrl/Command 全局互换。提供按目标设备的映射模式、覆盖规则和恢复默认，避免破坏终端、游戏、远程桌面及专业软件的物理按键习惯。
- 测试左右修饰键、组合键、按住释放、自动重复、Caps Lock、数字小键盘、ISO/ANSI/JIS、目标输入法、死键及中英文；系统保留快捷键、Fn/Globe、不可拦截安全组合按实际平台显示限制。切换或断线清理真实注入状态，不产生卡键或错误的本地点击。

### 鼠标

- 主机按目标保存移动比例、垂直和水平滚轮方向、滚轮倍率；定义与系统自然滚动、设备驱动加速度的关系，避免重复反转和重复加速。UI 标明当前目标及重置默认。高精度滚轮/触控板离散、连续事件、惯性与手势单独标记能力，无法表达时有明确降级。
- 常见五键、横纵滚轮及保持按下拖动进入测试矩阵；额外侧键按实际可捕获/可注入的标识协商。运动合并不得跨越按钮、滚轮和切换屏障而改变事件顺序。

### 剪贴板

- 默认仅在主机与当前正在控制的设备之间同步，切换目标时不向其他设备广播；用户可以全局关闭及按设备禁用，界面展示同步状态。只支持纯文本和常见静态图片（候选 PNG，实际格式协商），不读取/同步文件列表、应用私有格式或剪贴板历史；无远端控制目标时不主动向设备发送。
- 明确最大字节数、超限提示、目标格式转换、图片尺寸限制、错误处理；先做隐私及资源评估再定默认值。避免在日志中记录内容；通过唯一来源与变更 ID 去环、去重；严格按已配对设备授权转发，拒绝未知来源和重放。与输入消息分流或限流，图片不能堵塞键鼠与急停。
- 四平台、各桌面环境的后台剪贴板访问、用户授权、格式所有权与隐私限制必须真机验证，权限不足则清晰提示，不借助隐蔽读取。

## 6. 建议架构与安全设计

- 采用小型跨平台核心 + 原生平台适配器：核心负责拓扑、设备状态、协议、会话、按键语义映射、剪贴板去环、输入顺序和恢复策略；平台适配器提供采集/抑制、注入、权限、屏幕、剪贴板与原生 UI。核心语言、跨语言 ABI、构建依赖以 P0 原型评审后定，不预先承诺重写 Swift 或 ArkTS。平台能力通过显式 capability 集协商并在 UI 呈现。
- 推荐活动主机为星形路由中心：每个接收端与活动主机单独建立认证会话，主机统一管理布局和唯一输入焦点；允许接收端彼此不直接互信。设备之间的配对与主机手动交接要定义独立信任与重连语义。拓扑与设置本地持久化，密码材料放系统安全存储；设备名与网络地址不可当作身份。
- 鉴于新产品会传输键盘和剪贴板内容，v2 应采用有保密性和双向身份认证的成熟协议与经审查的密码库；设计配对时绑定双方公钥指纹、短码核对、重连验证、撤销与轮换，六位码不能单独承担抵抗主动中间人的任务。完整握手、身份绑定和用户核验方式先进行安全设计评审和负面测试，不自创密码算法，也不继承 v1 明文 token；不因加密失败静默回退明文。
- 帧尺寸/速率/队列有上限，先认证再分配高成本资源，控制消息与移动消息隔离；不要记录键盘、剪贴板、token 或私钥。设备发现只公布最少信息；只监听局域网接口，手动地址作为发现失败的备选。防火墙/多网卡/网段隔离须以实际网络为准。
- 恢复不变量：权限丢失、断网、心跳超时、休眠、锁屏、用户暂停、进程退出、布局变化和系统回收捕获时，主机优先恢复本地输入；目标尽力释放已注入的按键/鼠标按钮。提供可靠急停及独立备用键鼠；对 SIGKILL、断电或系统限制不能通过 finally 保证的路径记录实测边界。网络操作不能阻塞输入回调。

## 7. 界面与信息架构

1. 首次引导：语言、工作原理、系统授权、发现或手动连接、双方核验、角色选择、布局和首次安全测试；每步说明当前系统可能出现的权限提示。
2. 菜单栏/托盘：当前主机与控制目标、连接状态、暂停/恢复、回到本机、打开布局、快捷设置和退出；状态文字与颜色/图标同时表达。
3. 设备与布局：发现/添加/配对/重命名/解绑，显示离线和权限失败；空间画布可拖动，键盘可操作，边缘冲突可见，保存前校验。
4. 每设备设置：鼠标移动、双轴滚动方向/速度、快捷键适配模式、剪贴板权限、能力/限制及恢复默认；设置由当前主机保存并可辨认作用范围。
5. 隐私与诊断：系统权限状态、已信任设备、撤销访问、网络诊断和脱敏导出；不展示私钥或实际输入内容。
6. 无障碍与质量：中文/英文、键盘导航、屏幕阅读器、深浅色、缩放/高 DPI、小屏窗口；四平台保持相同信息架构并遵循各自系统习惯。先做可交互原型并用多种布局状态验证，再实现视觉规范。

## 8. 分阶段实施与验收门槛

所有阶段以可运行代码、记录和实际结果为准；允许并行推进互不依赖的工作，未通过门槛不称该阶段完成。

- **P0：基线与可行性**：复核现有测试与运行实例，不干扰用户现有工作；整理平台 API/受限权限/构建工具/设备矩阵；优先验证 Linux X11/Wayland 主客能力和 Windows 注入限制，鸿蒙主机合法性留待后续；产出架构决策、风险登记和 UI 原型。现有 Mac→鸿蒙 M1 的首次授权与真实输入需用户配合，保留备用键鼠。出口：本轮目标的各项能力均有可复现环境、结果、缺口与证据，不以头文件代替运行。
- **P1：v2 协议与共享内核**：完成设备身份、双向配对、加密、capability、焦点租约、布局/跨越、输入帧、剪贴板限流和恢复规范；golden vectors、分片/乱序/过期/伪造/重连/故障注入测试。先实现可模拟平台的真实核心，不动生产 v1 的安全路径。出口：跨语言互通及协议安全评审通过。
- **P2：Mac 与鸿蒙 v2 纵切**：复用已验证适配，完成加密配对、双端权限、目标设置、常用输入和剪贴板；Mac 主机→鸿蒙接收端先完成真机正反边缘及故障实测。鸿蒙主机须单独通过 P0 后实现。出口：真实机器连续操作、剪贴板、权限撤销与恢复证据完整。
- **P3：Windows 与 Linux**：逐个实现主机/接收端、系统服务/托盘、权限和安装流程；分别验证 Windows、Linux X11 和选定 Wayland compositor 的能力差异。出口：每个声明支持的系统/会话有真实双向输入、映射和恢复证据；不可用能力明确显示。
- **P4：多设备空间与体验**：三台及以上、包含两台不同系统接收端；验证上下左右、远端到远端、不同 DPI/缩放、离线与冲突、手动主机交接、每设备设置。出口：跨多设备连续穿越和故障恢复录证，UI 的可用性/无障碍检查通过。

## 9. 测试矩阵与质量指标

- 平台方向：本轮以 Mac、Windows、Linux 三平台作为主机 × 四平台作为接收端（包括同平台异机），至少覆盖每个声明支持的有序组合；鸿蒙主机留待后续，每个 Linux compositor 单列，不因部分组合通过填满整表。另测至少三设备、远端→远端、布局修改和手动主机交接。
