# Hop macOS implementation and evidence

## Scope and implementation

- Native Swift + AppKit; minimum macOS 14.0; Release targets `arm64` and `x86_64`. `LSUIElement=true`, accessory activation, one status item and one `NSPopover`; no main window. Sharing starts **disabled** until the user enables it.
- Real `Hop.xcodeproj` and shared `Hop` scheme. The CLT route directly compiles the same production Swift sources and constructs the application bundle; it is not a mock implementation.
- Native Network.framework TCP server on 24890. One accepted connection, including handshake, at a time; Bonjour `_hop._tcp`, TXT version + persistent Mac UUID only. All socket callbacks and writes use a dedicated serial queue. Writes are bounded to 256 frames; overflow fails closed. No networking blocks the input callback. Normal edge-state UI/layout updates are deferred out of the event-tap callback. Emergency/tap-disabled faults restore synchronously, then defer controller stop/network/UI work to the main queue with tap-generation and connection-ID guards; drain completion also defers tap removal.
- Exact fixed 128-byte binary bodies, big-endian length prefix/integers, strict fields/reserved bytes/roles/epochs/UTF-8 validation; bounded incremental decoding handles fragmentation and concatenation without allocating attacker-declared lengths.
- Pairing is explicitly opened from the popover for 60 seconds. SecureRandom rejection-sampled six-digit code and a random 32-byte token. The token is withheld until both local and remote confirmations. Keychain persists the peer UUID/token/name only after matching client COMMIT acknowledgement; resume uses constant-time byte comparisons. A double-confirmed in-process candidate can recover a lost COMMIT connection until expiry. Rejections/cancellation clear the candidate; reconnect never silently downgrades to PAIR. Unpair restores locally first, sends authenticated BYE reason4, deletes Keychain binding, and clears candidates.
- Permission flow requests Accessibility and Input Monitoring and links Privacy & Security settings. No event tap exists until explicitly enabled and permissions pass. Revocation, tap disable, heartbeat/transport/protocol faults, emergency Ctrl+Option+Command+Esc, session lock/sleep, display changes, disable and quit all route through synchronous idempotent restoration.
- Active CGHID `CGEventTap`, hardware-origin PID filter, physical keycodes and left/right modifier state. No characters or input-method conversion. Unsupported keys are swallowed while remotely controlling, where capturable. Already-held nonmodifier keys postpone crossing because ENTER cannot reconstruct them.
- Crossing sends ENTER but does not hide/disassociate or swallow until exact successful ACK within300ms and unchanged local button/modifier/edge state. Pending events pass through; leaving the edge or state changes cancels and sends LEAVE. Remote coordinates integrate captured deltas independently of the frozen Mac cursor. One-slot movement coalescing ticks at120Hz; every key/button/wheel flushes the latest movement first. Five buttons, drags, wheel, physical keys/repeat/side-specific modifiers/Caps Lock are encoded using the frozen protocol.
- One restoration routine first sets LOCAL (ends blanket remote capture), clears pending movement/ENTER and forwarding key/button/modifier state, re-associates, shows cursor, and warps only if capture actually happened; then the controller handles LEAVE/BYE/persistence/UI. A separate pure physical-ownership ledger deliberately survives restoration: every observed remotely swallowed key/button down (including unsupported codes/buttons) retains ownership through repeats, release and button drag tails. It never synthesizes local clicks or keys. Failed association/show calls keep recovery flags and retry on a later timer tick without resuming blanket capture.
- ENTER snapshots locally pre-held modifiers and buttons as LOCAL-owned. While remote, motion/new input remains captured, but those pre-held physical releases are forwarded to the peer AND allowed through locally so the original local down is not left stuck. Subsequent presses acquire fresh ownership. After restoration, remote-owned repeats/ups/drags are swallowed until physical release; unrelated new local input passes. Remote-only Shift/Control/Option/Command groups (and captured Fn where represented by the canonical resource) are stripped from passing hardware-event flags, without clearing a group still held by a locally-owned opposite-side modifier.
- Disable/stop retains a usable tap in drain-only LOCAL mode only while remote-owned presses remain; it cannot re-enter while draining. Final release schedules guarded tap removal outside the callback. Re-enable can reuse that tap without resetting ownership. Restart after tap removal reconciles tracked entries against physical state, discarding missed releases. Quit and permission loss deliberately remove the tap immediately; a disabled/lost tap cannot enforce quarantine. No claim is made that release tails are suppressed once the tap/process is unavailable. Emergency detection restores first, never forwards its Escape trigger, and quarantines that trigger's repeat/up tail while a usable tap remains.
- The wire sends Mac keycodes. The bundle keymap is generated by `scripts/generate-resources.py` from the sole canonical `../../protocol/keymap.json`; no second handwritten map exists. Both CLT build and Xcode pre-build regenerate it. Physical supported-key/modifier/escape lookup derives from this resource, which is parsed once at launch. No Deskflow code was copied or used.

## Commands

From the repository root:

```sh
bash apps/macos/scripts/build.sh       # Universal native app, ad-hoc signature; NEVER launches it
bash apps/macos/scripts/test.sh        # Offline core/safety tests + localhost transport integration
bash apps/macos/scripts/verify.sh      # Both commands and machine-readable report/log
bash apps/macos/scripts/package.sh    # Universal ad-hoc .app zip, not Developer ID/notarized
bash apps/macos/scripts/xcode-build.sh # Full Xcode route, when Xcode is installed
```

`HOP_ARCHS='arm64 x86_64'` (default) controls the CLT build. `HOP_BUILD_DIR` can select a different output directory. No script changes global `xcode-select`, grants permissions, starts the graphical app, captures input, or writes a real pairing binding during testing.

The Xcode route uses `xcodebuild -project apps/macos/Hop.xcodeproj -scheme Hop -configuration Release -destination 'generic/platform=macOS' ARCHS='arm64 x86_64' ONLY_ACTIVE_ARCH=NO CODE_SIGNING_ALLOWED=NO build` and a workspace-local DerivedData directory. The CLT route produces an ad-hoc signed bundle at `build/Hop.app`; packaging produces `build/Hop-macos-universal-adhoc.zip`.

`verify.sh` writes `build/critique/build-test.json` and `build-test.log`, including command exit codes, durations, build.passing/tests.passing and `runtimeInputVerified:false`.

## Runtime boundary / required manual acceptance

**The graphical application has NOT been launched. No real keyboard or mouse input has been captured. No real permission grant, Keychain interaction, Bonjour discovery, remote injection, or GUI behavior was verified.** Headless loopback tests use an in-memory pairing binding and explicitly coordinated test-only confirmation; production pairing does NOT auto-confirm. Apple Developer ID certificates, notarization and distributable trust are not claimed.

Before coordinated two-device acceptance, explicitly grant permission to run Hop/capture input, keep a physical fallback mouse/keyboard, and test:

- App opens only in menu bar; popover fits normal/pairing states; permission prompts/restart behavior, enable/disable, paired name/direction/pair/reject/unpair/quit.
- Same code displayed on both ends; neither unilateral confirmation yields a token; Keychain survives process restart; token rejection requires explicit re-pair; offline unpair and COMMIT-loss recovery.
- Actual Network.framework firewall/local-network prompts, Bonjour discovery and reconnect after LAN loss.
- Intel runtime (cross-compilation alone is NOT Intel runtime verification), macOS14 runtime, Retina/non-Retina scaling and left/right main-display crossing.
- ENTER positive ACK gates cursor hiding/association; no-ACK, changing button/modifier state, leaving edge, late ACK, and entering while holding a nonmodifier key.
- Real delta behavior at120Hz, five buttons, clicks, remote drags, natural-scroll direction on both wheel and trackpad, all mapped physical keys, repeats, side-specific modifiers, Caps Lock and input methods.
- Local restoration FIRST on Ethernet/Wi-Fi loss, malformed peer frame, peer crash, slow writes, heartbeat silence, tap disable, permission revoke, display change, sleep/session lock, disable, quit and emergency Ctrl+Option+Command+Esc.
- Crash/SIGKILL/power loss: verify macOS process cleanup restores event tap/cursor association/visibility, because no finally block can run after process death. This is explicitly not proven by source or fake cursor tests.
- No local phantom clicks/key presses when returning with remote-held inputs; client releases its actual injected sets. Exercise unsupported keycodes/buttons, remote autorepeat, drags-until-release, mixed left/right modifiers, fresh local input during disable-drain, and re-enable before drain completes.
- The pre-held LOCAL release exception is deliberate: it may complete a local click/drag begun before crossing, but avoids leaving that application with an unmatched local down. Validate this policy against actual macOS applications and the protocol's otherwise-remote-capture behavior. No release-only synthetic event or synthetic local down is posted.
- Quarantine depends on observing the relevant down/up through a live permitted tap. Tap timeout/permission loss, Secure Input/system-reserved input, disconnecting a device without an up, process termination and events delivered while disabled can bypass or prevent drainage; stale entries are reconciled only when starting a new tap. Caps Lock flagsChanged is treated as a latch transition, not a physical down/up stream, and is not kept quarantined until the next toggle. Hardware/device-dependent modifier flags, system shortcut interception, Fn/Globe and Caps Lock state, HID query timing, and the effectiveness of stripping remote-only event flags all require real runtime acceptance. Event flag editing cannot promise to change macOS's underlying global physical/latch state.

These remain unverified until actual coordinated runtime/device tests. Mock and offline success do not satisfy real HarmonyOS injection or end-to-end milestone exits.
